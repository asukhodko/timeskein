## Рабочее название и метафора

**Timeskein** — система "личного контекстного журнала", которая помогает структурировать рабочую активность в **эпизоды и нити смысла** (threads), чтобы можно было быстро отвечать на вопросы:

- "Что я делал в момент X?"
- "Когда и как я решал проблему Z?"
- "Что полезного я сделал за день Y?"
- "Какие темы/проекты доминируют и какие хвосты не закрываются?"

Название — метафора мотка нитей: активность запутана во времени и смыслах, а Timeskein помогает этот моток **распутывать**.

## Зачем это нужно

Человеческая память о работе обычно хранится не в "задачах", а в фрагментах контекста:

- где был открыт документ,
- в каком тикете обсуждали проблему,
- какие вкладки и заметки были рядом,
- кто и что обещал прислать.

Эти фрагменты распадаются, и человек теряет ответ на главный вопрос:  
**"Что у меня сейчас на столе и что с этим делать дальше?"**

Timeskein проектируется как система, которая:

1. помогает фиксировать контекст работы (вручную или автоматически),
2. сохраняет его локально (local-first) и приватно,
3. позволяет восстанавливать "картину" по времени и по смыслу.

## Принципы

1. **Local-first обработка**  
   Предобработка и хранение по умолчанию — на устройстве. Сервер (если появится) — опционален.

2. **Минимизация данных по умолчанию**  
   Храним ровно столько, сколько нужно для функций. "Видеорегистратор жизни" — анти-цель.

3. **Управляемая чувствительность**  
   Данные помечаются по чувствительности (обычные / приватные / чувствительные). Политики хранения, синхронизации и показа зависят от этой маркировки.

4. **Провенанс (проверяемое происхождение)**  
   Каждое сохранённое наблюдение знает источник, время и применённые правила (редакция/фильтры).

5. **Отказоустойчивость и оффлайн-режим**  
   Устройство может быть без сети: "собрал → сохранил локально → синхронизировал позже".

6. **Портируемость**  
   Данные не заложники UI: экспортируемые форматы и стабильные схемы данных.

7. **Manual-first как базовый режим доверия**  
   Ручной режим всегда работает, почти без разрешений. Автоматизация добавляется как опциональный слой, включаемый пользователем.

## Эволюционные уровни зрелости

Система развивается по уровням, каждый из которых **не ломает** предыдущий:

| Уровень | Название | Описание | Разрешения |
|---------|----------|----------|------------|
| **Level 0** | Manual-first | Ручной реестр Work Items, refs, заметки | Минимальные (файловая система) |
| **Level 1** | Sync | Синхронизация между устройствами | + сетевые (локальный hub) |
| **Level 2** | Semantics-first | Явный захват контекста по команде; connectors | + разрешения конкретных источников |
| **Level 3** | Full context | Always-on collectors (по включению пользователя) | + системные разрешения |

**Принцип:** ручное состояние (`state`, `note`) остаётся источником истины пользователя на всех уровнях.

## Модель мира (целевое состояние)

### Основные сущности

- **Work Item** — элемент работы (task/project/question) с состоянием, заметками и привязками.
- **Ref** — привязка к "миру" (URL, файл, ключ тикета, repo/issue).
- **Event** — атом наблюдения:
  - **WorkItemEvent** — изменение Work Item (Level 0+)
  - **ContextEvent** — событие внешнего контекста (Level 2+)
- **Artifact** — вложение к событию (скриншот, текст, транскрипт) — опционально (Level 3).
- **Evidence Artifact** — chunk screen evidence с TTL (Level 3, opt-in). Канонический тип = chunk.
- **Episode** — интервал с единым контекстом (производное, Level 2+).
- **Timeline Card** — derived view/presentation of Episode (Level 2+). Cards = UI view, Episodes = domain model.
- **Thread** — сквозная тема/проект, связывающая эпизоды (производное, Level 2+).
- **Mark** — пользовательский маркер ("важно", "закрыл", "вернуться").
- **Distraction Mark** — авто-mark для классификации off-task активности (Level 3).

### Capture Profile

Профиль захвата данных, определяющий уровень автоматизации:

| Уровень | Название | Описание |
|---------|----------|----------|
| Level 0 | Manual-first | Без фонового сбора |
| Level 2 | Semantics-first | Явный захват по команде |
| Level 3 | Full context | Always-on collectors (opt-in) |

### Evidence-Mode (Level 3, opt-in)

**Evidence-Mode** — строго opt-in функция Level 3 для захвата screen evidence chunks и их дистилляции в Timeline Cards/Episodes.

**Ключевые принципы:**
- **Строго opt-in:** никогда не включается по умолчанию
- **Chunking model:** канонический тип артефакта — `chunk` (серия кадров)
- **Privacy-first:** короткий TTL (72h), pause/resume, purge, redaction rules
- **Manual-first сохраняется:** Evidence-Mode расширяет, но не заменяет ручное управление

**Важно:** Evidence-Mode — сенсор для восстановления контекста, НЕ трекер дисциплины. Work Items остаются источником истины.

См. [ADR-0003: Evidence-Mode Opt-in](adr/0003-evidence-mode-opt-in.md) и [RFC-0007: Screen Evidence Source Node](rfc/0007-evidence-mode-screen-evidence-source-node.md).

### Архитектурные компоненты

- **TS-AGENT** — локальный агент, центральная точка правды на устройстве.
- **Surface** — UI-клиент (CLI, трей, мобильное приложение).
- **SourceNode** — источник событий (Collector, Connector, Extension) — Level 2+.
- **Screen Evidence SourceNode** — специализированный Collector для Evidence-Mode (Level 3, opt-in).
- **Provider** — абстракция AI-провайдера для обработки артефактов (local/remote) — Level 2+.
- **PolicyGate** — шлюз политик приватности на входе событий.
- **Hub** — серверный компонент для синхронизации — Level 1+.

### Pipeline (обработка данных)

Цепочка обработки данных Evidence-Mode:

**Capture → Distill → Present → Cleanup**

- **Capture:** захват screen evidence chunks
- **Distill:** извлечение ценности через Provider (OCR, summarization)
- **Present:** отображение в Timeline Cards
- **Cleanup:** удаление по TTL с сохранением Distilled Snapshots

### Слои данных

- **Canonical** — события/журналы (append-only, объяснимые).
- **Derived** — эпизоды/нити/индексы (пересчитываемые).
- **Ephemeral** — тяжёлые артефакты (с TTL).

### Плоскости системы

- **Data Plane** — как данные хранятся и передаются.
- **Control Plane** — управление источниками, разрешениями, политиками, здоровьем.

## MVP: первая полезная функция (Level 0)

MVP ориентирован на одну функцию:

> **"Ручной инвентарь текущей работы"** — список актуальных задач/проектов/вопросов и их состояние.

В MVP Timeskein строит **реестр Work Items**, который поддерживается **вручную** (Manual-first):

- Пользователь сам создаёт Work Items
- Пользователь задаёт состояния и заметки
- Пользователь добавляет привязки (refs) вручную
- `last_seen` обновляется по явным действиям пользователя в Timeskein

**MVP не включает:**
- Фоновое наблюдение за окнами/вкладками
- Автоматическое обновление `last_seen` по посещениям refs
- ContextEvent log
- Collectors (active window, browser context)

См. [ADR-0002: MVP = Manual-first](adr/0002-mvp-manual-first.md) для обоснования.

## Границы MVP (анти-цели для первой версии)

- Не делаем "полное восстановление дня" и "умные нити" (threads) как обязательную часть.
- Не делаем запись экрана/аудио по умолчанию.
- Не делаем обязательный сервер и облачную зависимость.
- Не встраиваемся глубоко во все таск-трекеры; вместо этого поддерживаем **привязки (refs)**.
- **Не делаем фоновое наблюдение** — это Level 2/3.

## Высокоуровневая архитектура (MVP)

- **Локальный агент (TS-AGENT)**:
  - ведёт реестр Work Items и их состояния,
  - хранит привязки (refs) и события изменений (WorkItemEvents),
  - обслуживает запросы от Surface.

- **Локальное хранилище**: SQLite (с индексами; без тяжёлых артефактов).

- **UI/команды (Surface)**:
  - "Показать инвентарь"
  - "Создать Work Item"
  - "Поставить состояние: active/waiting/blocked/done/someday"
  - "Добавить заметку: следующий шаг/затык"
  - "Добавить/открыть привязку (ref)"
  - "Touch" — отметить возврат к задаче

## Дальнейшее расширение (после MVP)

### Level 1: Sync
- Синхронизация между устройствами
- Hub как опциональный сервер

### Level 2: Semantics-first
- Явный захват контекста по команде ("Capture current context")
- Connectors к приложениям (browser extension, GitHub, Slack)
- ContextEvent log
- Episodes как производное представление
- Подсказки по сильным refs

### Level 3: Full context
- Always-on collectors (active window, idle)
- **Evidence-Mode (opt-in):** screen evidence chunks с дистилляцией в Timeline Cards
- Threads и граф связей
- Семантический поиск (эмбеддинги)
- Артефакты (скриншоты, транскрипты) с TTL
- Политики чувствительности и редакции (PII)
- Provider abstraction (local/remote AI)
- Storage Budget и GC для Evidence Artifacts
