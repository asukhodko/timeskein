# Causal Work Spine + Operational Reality v1: Acceptance Audit

## Статус

**Принято 2026-07-16.** Реализация и двухдневный пользовательский dogfood-gate
доказаны. `Рабочая реальность` использовалась как точка выбора и продолжения
работы 15 и 16 июля; строгий gate прошёл без послаблений.

Dogfood 2026-07-10 подтвердил прежний дневной контур: `5:57:50` учёта,
18 входов, две коррекции, финальное закрытие за `2:08`, без ошибок API. Этот
день не входит в двухдневный шлюз: приложение было запущено до появления
Operational Reality, а в рабочей базе после закрытия ещё не было таблицы
`causal_records`. Это зафиксированный нулевой замер, а не частичное выполнение
нового gate.

Дни 2026-07-13 и 2026-07-14 подтвердили обновлённый общий контур: оба дня
закрыты, 14 июля диспетчеризация сохранила выбор и запустила первое дело. Строгий
`operational-reality:gate` при этом корректно показал `0/2` дней и `0/3`
стартов из Рабочей реальности, отсутствие подтверждённого рабочего состояния,
коррекции, Reflection follow-up и полной причинной цепочки. Эти дни остаются
регрессионным доказательством дневного контура, но двухдневный M1 gate нужно
пройти заново через новый явный путь `Начать отсюда`. Повторный прогон 15–16
июля этот gate закрыл.

Дополнительный аудит обнаружил и закрыл две границы:

- superseded result больше не считается текущим после переклассификации или
  удаления typed evidence; исходная запись остаётся в causal history;
- follow-up к legacy Reflection decision supersedes причинное решение и убирает
  его из текущей проекции, сохраняя корректный исторический `as_of`.
- карточка Track использует результаты и решения связанных Work Item по
  историческому Track-снимку, а не по их текущей классификации; captured Refs
  остаются видимыми как основания направления.
- обычный legacy Work Item с неизвестным состоянием и без следующего действия
  остаётся доступен через `Показать всё`, но не попадает в основную очередь
  решения без дополнительного сигнала; проверка на копии реальной базы снизила
  очередь с 46 до 8 пунктов, не удалив ни одного из 46 пунктов проекции.

| Устойчивая ручная коррекция | correction с `supersedes_id`: `1/1` | пройдено |
| Исправление пережило перезапуск | `app_started` позже последней correction | пройдено |
| Reflection follow-up | `3/1` | пройдено |

| Полная причинная цепочка | Реальное обращение с MR: intent -> результаты -> Ref -> next action | пройдено |

Строгая команда:

```bash
pnpm operational-reality:gate -- --from 2026-07-15 --to 2026-07-17
```

дала итог `пройдено`: два дня, 11 стартов из проекции, четыре реальных особых
состояния, коррекция с последующим перезапуском, три Reflection follow-up, одна
полная причинная цепочка и два обычных закрытия.

Пользовательский результат подтверждён на реальном обращении с MR: Timeskein провёл дело от
неопределённого обязательства через конкретные следующие действия к пониманию
причины буксования и отправленному ответу, сохранив URL как evidence. На второй
день договор ограничил работу двумя направлениями, а координация заняла `7:18`
вместо `1:38:19` днём ранее.

## Дефект доверия, найденный при приёмке

16 июля два остановленных блока пересеклись на `9:05`, а старое закрытие дня
ошибочно сочло данные чистыми. После dogfood:

- API запрещает создавать или исправлять остановленный блок так, чтобы он
  пересекался с другим блоком;
- интерфейс, CLI-закрытие и RC-проверка считают уже существующее пересечение
  красным блокером;
- отчёт за период сохраняет строки, но добавляет явное предупреждение
  `overlapping_focus_sessions`;
- исправление покрыто Rust, TypeScript и сквозными smoke-тестами.

Исторические строки 16 июля автоматически не переписываются. До ручной
коррекции повторное закрытие этого дня остаётся черновиком, что честнее
прежнего финального статуса.

Перед первым засчитываемым днём устранены трения нулевого замера:

- поиск по делам стал регистронезависимым для Unicode и терпимым к смешанным
  кириллическим/латинским омоглифам;
- `Enter` открывает редактор, если основная ссылка не является URL;
- разделитель меняет высоту всей верхней рабочей области, а не только списка
  фокус-блоков;
- диспетчеризация явно ограничивает активный набор, объясняет действия кнопок
  и умеет учитывать собственное время в зоне `Координация`;
- пакет вечерних проверок показывает все входящие в него пункты, а не только
  непрозрачное число.

После нулевого прогона 13–14 июля также:

- сохранённый результат диспетчеризации остаётся на экране как компактный
  договор на день и может быть возвращён в форму для пересмотра;
- главный старт из Рабочей реальности поднят в заголовок выбранного пункта и
  назван `Начать отсюда`, чтобы его нельзя было спутать с обычным стартом;
- отметка просмотра зон объясняет счётчик и дневной ориентир;
- обычный `dogfood:start` стал быстрым ежедневным входом, а полный preflight
  вынесен в `dogfood:start:verified` после изменения кода.

Финальная машинная проверка:

```bash
pnpm operational-reality:gate \
  -- --from YYYY-MM-DD --to YYYY-MM-DD
```

`--to` не включается. Зелёная команда доказывает сохранённую фактуру, но
последний пользовательский критерий остаётся смысловым: назвать конкретный
выбор, который стал возможен без ручной археологии по внешним заметкам.
