# Working Memory Bridge v1: аудит приёмки

## Статус

**Реализация готова, продуктовая приёмка продолжается.**

Автоматические проверки доказывают модель данных, сохранность после
перезапуска, API/mock/UI/CLI, исторические снимки, объединение дублей и
детерминированность Context Pack. Цель намеренно остаётся незавершённой:
необходимо пройти реальный путь D0, D1, D4 и D11 на одном долгосрочном деле без
внешнего блокнота.

Выбрано дело `ППП`
(`6f763920-6b77-4398-8895-ecdb9f0b55d6`). На 8 августа мягкий gate показывает
стадию `подготовка D0`: четыре записи памяти, Track, пять этапов, два перехода и
дневные снимки уже есть, но свежая запись и материал ещё не были сохранены до
старта одного квалифицирующего блока; также отсутствуют редакция и полный
причинный след остановки. Календарный отсчёт возвратов пока не начался.

Семь обычных рабочих дней с 30 июля по 7 августа дали `52:13:58` трекинга и
104 входа, включая `12:18` по `ППП`, но не добавили новых записей памяти,
материалов или возвратов. Эти данные считаются естественной исходной линией,
а не принятой частью D0–D11.

## Текущий реальный gate

Команда:

```bash
pnpm working-memory:gate -- \
  --work-item 6f763920-6b77-4398-8895-ecdb9f0b55d6 \
  --from 2026-07-23 \
  --to 2026-08-09 \
  --soft-fail
```

Состояние на 8 августа:

| Проверка | Факт |
|---|---:|
| Стадия | подготовка D0 |
| Наблюдаемый период | 0/7 дней |
| Запись памяти до старта D0 | нет |
| Материал до старта D0 | нет |
| Записи памяти | 4/6 |
| Семантические записи | 1/3 |
| Материалы | 0/1 |
| История редакций | нет |
| Именованные этапы | 5/2 |
| Переходы этапов | 2/1 |
| Снимки дневного результата | 11/1 |
| Полные причинные следы | 0/2 |
| Возвраты 1/3/7 | 0/3 |
| Track | назначен |
| Ошибки API и действий в старом диапазоне | 12 |
| Пересечения focus-блоков | 0 |

Следующее доказательство: до старта нового блока добавить в память `ППП`
смысловую запись и материал, проверить активный этап, затем остановить
реальный блок с полями `сделал → изменилось → следующий шаг`. Gate проверяет
порядок по `recorded_at`, поэтому подготовка задним числом D0 не создаёт.

Плановый чистый диапазон начинается 10 августа, поэтому прежние отклонённые
коррекции не попадут в итоговый gate. Любая новая ошибка в диапазоне D0–D11
останется видимой как потенциальная регрессия.

## Реальная последовательность

| Точка | Минимальная пауза | Что доказывается |
|---|---:|---|
| D0 | базовый день | Полная рабочая память и причинная точка возвращения созданы |
| D1 | 1 день после D0 | Первый возврат начинается из сохранённого next action |
| D4 | 3 дня после предыдущего возврата | Контекст выдерживает среднюю паузу и переход этапа |
| D11 | 7 дней после предыдущего возврата | Долгое дело продолжается без внешней реконструкции |

На каждом возврате нужно запустить новый фокус именно через `Начать отсюда`,
затем остановить именно этот блок с новым полным причинным следом. Gate связывает
возврат с точным `focus_session_id`: неуспешный запуск, повторное нажатие для уже
активного блока или соседний ручной старт не засчитываются. В ходе прогона
должны появиться минимум два этапа, один переход, один материал, несколько
смысловых записей и оба профиля Context Pack в UI, Markdown и JSON. Финальные
проекции нужно построить и экспортировать после последнего принятого возврата,
чтобы они отражали итоговое состояние D11.

## Автоматические проверки

После последнего статического усиления gate на 8 августа повторно проходят:

```bash
pnpm test
pnpm typecheck
pnpm lint
pnpm roadmap:validate
pnpm smoke:dogfood-docs
git diff --check
```

`pnpm lint` завершается без ошибок и сообщает 15 существующих предупреждений
React Hooks в компонентах вне Working Memory.

Перед D0 полный `pnpm dogfood:preflight` должен собрать release-версию
`Timeskein.app`, проверить нативный бинарник, SQLite и восстановление
фокус-сессии после перезапуска. После D11 тот же preflight повторяется перед
финальной приёмкой.

Финальная приёмка повторно требует:

```bash
pnpm dogfood:preflight
pnpm smoke:macos-app
pnpm working-memory:gate -- \
  --work-item 6f763920-6b77-4398-8895-ecdb9f0b55d6 \
  --from D0_DATE \
  --to DAY_AFTER_D11
```

## Правило завершения

Зелёный gate необходим, но недостаточен. Пользователь должен содержательно
подтвердить, что после семидневной паузы понял ход работы, причины решений и
следующий физический шаг по одному Timeskein. Если контекст пришлось
восстанавливать по внешнему блокноту или памяти, цель не принята.

После этого фактические выводы добавляются сюда и в Roadmap 0005, определяется
следующий вертикальный срез Causal Period Review, изменения делятся на
осмысленные коммиты и отправляются в `origin/main`.
