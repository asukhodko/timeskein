# ADR-0002: MVP = Manual-first (Level 0)

## Статус

**Принято**.

## Уровень зрелости

**Level 0** (Manual-first)

## Контекст

В процессе разработки документации Timeskein образовалось противоречие между двумя линиями описания MVP:

### Линия A: "Минимальные коллекторы уже в MVP"

- `docs/00_project_overview.md` описывал MVP как инвентарь, обновляемый "автоматически по контексту (окна/URL) и вручную".
- `docs/adr/0001-initial-architecture.md` закладывал в MVP `ContextEvent log`, watcher активного окна, browser context.
- `docs/mvp/01_user_story_inventory.md` описывал "создать/привязать из текущего контекста" и авто-обновление `last_seen`.

### Линия B: "Manual-first без фонового наблюдения"

- `docs/mvp/02_user_story_manual_inventory.md` прямо фиксирует: "никакого фонового наблюдения, только явные действия пользователя".
- `docs/mvp/02_manual_inventory_ui_ux.md` подтверждает: "Timeskein ничего не записывает в фоне".
- `docs/roadmap/0001-mvp-execution-roadmap.md` поддерживает manual-first как точку старта.

Это не стилистическая разница, а **разные философии доверия, разрешений и сбора данных**.

## Решение

**MVP Timeskein определяется как Manual-first (Level 0).**

Это означает:

1. **Никакого фонового наблюдения** — нет слежения за активными окнами, вкладками, вводом, скриншотов.

2. **Все действия явные** — Work Items создаются, редактируются и "трогаются" только по явному действию пользователя внутри Timeskein.

3. **`last_seen` обновляется вручную** — через touch/edit/open, не автоматически по посещениям refs.

4. **Refs добавляются вручную** — paste/выбор файла/ручной ввод; нет авто-извлечения из текущего контекста окна.

5. **ContextEvent log не является частью MVP** — это будущий контур (Level 2/3).

6. **Collectors (active window, browser context) не являются частью MVP** — это будущий контур (Level 2/3).

## Эволюционные уровни зрелости

MVP — это **Level 0**. Система развивается по уровням:

| Уровень | Название | Описание | Разрешения |
|---------|----------|----------|------------|
| **Level 0** | Manual-first | Ручной реестр Work Items, refs, заметки | Минимальные (файловая система) |
| **Level 1** | Sync | Синхронизация между устройствами | + сетевые (локальный hub) |
| **Level 2** | Semantics-first | Явный захват контекста по команде; connectors | + разрешения конкретных источников |
| **Level 3** | Full context | Always-on collectors (по включению пользователя) | + системные разрешения (accessibility, screen) |

Каждый уровень **не ломает** предыдущий:
- Ручное состояние (`state`, `note`) остаётся источником истины пользователя.
- Автоматизация добавляется как опциональный слой.
- Пользователь явно включает каждый источник данных.

## Последствия

### Что меняется в документации

1. **ADR-0001** уточняется: collectors и ContextEvent log помечаются как "заложено для Level 2/3", не как MVP.

2. **User Story 01** (`mvp/01_user_story_inventory.md`) переквалифицируется как Level 2 feature ("Захват текущего контекста по команде").

3. **RFC-0001** разделяется на Part A (Level 0, нормативная) и Part B (Level 2/3, расширение).

4. **Project Overview** обновляется с явным указанием Manual-first MVP и уровней зрелости.

### Плюсы решения

- **Минимальные риски приватности** — нет сбора чувствительных данных в MVP.
- **Быстрый запуск** — меньше кода, меньше разрешений, меньше edge cases.
- **Прочный фундамент** — модель Work Items не зависит от наличия collectors.
- **Доверие пользователя** — система делает ровно то, что говорит.

### Компромиссы

- MVP требует дисциплины от пользователя (ручное ведение реестра).
- "Умные" функции (авто-привязка, подсказки) откладываются.
- Ценность MVP зависит от готовности пользователя вносить данные вручную.

## Рассмотренные альтернативы

### Альтернатива 1: MVP с минимальными collectors

Включить хотя бы active window watcher в MVP для автоматического `last_seen`.

**Отклонено**: требует системных разрешений (accessibility), усложняет приватность, размывает границу "что система знает".

### Альтернатива 2: MVP с browser extension

Включить browser extension для авто-извлечения URL/title.

**Отклонено**: требует публикации расширения, поддержки нескольких браузеров, политик приватности браузера.

### Альтернатива 3: "Умолчания" — ручной режим с выключенными collectors

Collectors есть в коде, но выключены по умолчанию.

**Отклонено для MVP**: увеличивает объём кода до первой пользы; лучше добавить collectors когда ручной режим стабилен.
