# Operational Reality Dogfood

## Цель проверки

Проверить на двух реальных рабочих днях, помогает ли `Рабочая реальность` выбирать и возобновлять работу по сохранённым основаниям, а не по памяти и последнему входящему сообщению.

Сырые выгрузки остаются локальными. В них могут быть рабочие названия, внутренние ссылки и личные формулировки.

## Результат

Gate принят 2026-07-16 по реальным рабочим дням 15 и 16 июля:

- `2/2` дней со стартом из `Рабочей реальности`;
- `11/3` стартов кнопкой `Начать отсюда`;
- реальные состояния `meeting-tail`, `stale-important`, `waiting`, `reactive`;
- одна явная коррекция, пережившая перезапуск;
- три Reflection follow-up;
- одна полная цепочка `intent -> result с Ref -> next action`;
- обычное закрытие `2/2` дней.

```bash
pnpm operational-reality:gate -- --from 2026-07-15 --to 2026-07-17
```

Команда завершилась с итогом `пройдено`. Конкретное доказательство причинного
пути получено на обезличенном реальном обращении с MR: старт из
проекции, последовательные следующие действия, найденная причина остановки MR,
отправленный ответ и URL-ссылка как evidence.

Приёмка также обнаружила пересекающиеся фокус-блоки 16 июля. Код теперь
запрещает новые пересечения, блокирует финальное закрытие для старых и выводит
предупреждение в отчёте за период. Исторические данные оставлены для ручной
коррекции.

## Перед первым днём

Собрать и открыть актуальную macOS-версию:

```bash
cd /Users/a.sukhodko/dalamar81/timeskein
pnpm dogfood:start:verified
```

Последующие дни на той же сборке начинаются быстрым `pnpm dogfood:start`.

Если текущий день уже начат этой сборкой:

```bash
pnpm dogfood:continue
```

Не очищать базу между двумя днями. Operational Reality проверяет накопленную причинную память.

День 2026-07-10 был выполнен на сборке до Operational Reality. Дни 13 и 14 июля
подтвердили общий дневной контур, диспетчеризацию и закрытие, но не вошли в
Operational Reality gate: ни один фокус-блок не был начат кнопкой панели, не
было подтверждения/исправления состояния, Reflection follow-up и полной
причинной цепочки. Это полезный нулевой прогон нового интерфейса, а не
частичное прохождение продуктового сценария.

При первом открытии сравнить основную очередь с `Показать всё`. Обычные старые
дела должны оставаться во второй выборке, не заполняя основной экран. Если
основная очередь снова выглядит как весь инвентарь, зафиксировать это как
регрессию и не разбирать все пункты вручную.

## Что делать в течение двух дней

1. Открывать `Рабочую реальность` в начале дня и после заметного перерыва. Рабочий путь: выбрать пункт слева -> сверить `Почему здесь` и основания -> подтвердить или исправить состояние -> записать физический следующий шаг -> начать фокус.
2. Не менее трёх раз начинать реальное дело кнопкой `Начать отсюда` именно в заголовке выбранного пункта. Старт должен быть распределён минимум по двум календарным дням. Обычный старт, старт из списка и старт из диспетчеризации в этот счётчик не входят.
3. Для действительно встреченных дел подтверждать или выбирать подходящее состояние: ожидает, заблокировано, припарковано, реактивное, завершено, важное без движения, хвост встречи. Не нужно искусственно использовать все состояния.
4. Хотя бы один раз исправить уже сохранённое состояние и написать причину. Старое утверждение должно остаться в истории, новое должно явно его заменить.
   После исправления перезапустить Timeskein через `pnpm dogfood:continue` и
   убедиться, что исправленное состояние сохранилось.
5. Для одного реального пункта записать физически выполнимое следующее действие. Позже отметить его выполненным, неактуальным или заменить новым.
6. Хотя бы один раз проверить решение из прошлого Reflection Session через блок `Проверить решение прошлого обзора`.
7. Для одного Work Item собрать причинную цепочку:
   - нажать `Начать отсюда`: Timeskein автоматически сохранит намерение, отдельную запись типа «Мысль» создавать не нужно;
   - во время или после блока записать `Результат`;
   - приложить Ref к результату;
   - записать `Следующий шаг` после результата.
8. Если проекция ошибается, исправлять её в приложении. Не править SQLite вручную.

## После каждого дня

В интерфейсе завершить обычную `Проверку перед отчётом` до финального
`Копировать отчёт`, затем сохранить артефакты:

```bash
pnpm dogfood:finish:save
```

Сохранить диагностический снимок проекции:

```bash
pnpm export:operational-reality \
  -- --output /tmp/timeskein-operational-reality-YYYY-MM-DD.json
```

В короткой заметке ответить на три вопроса:

- Какое дело я выбрал или продолжил благодаря панели?
- Какое основание оказалось полезным или неверным?
- Стал ли следующий шаг яснее и дешевле для входа?

## Финальный шлюз после второго дня

Верхняя граница не включается. Принятый прогон проверял 15 и 16 июля:

```bash
pnpm operational-reality:gate \
  -- --from 2026-07-15 --to 2026-07-17
```

Команда читает реальную локальную SQLite-базу и требует:

- два дня со стартами из `Рабочей реальности`;
- не менее трёх таких стартов;
- хотя бы одну явную коррекцию состояния;
- перезапуск приложения после последней коррекции;
- хотя бы одну проверку прежнего Reflection-решения;
- хотя бы одну цепочку `намерение -> результат с Ref -> следующий шаг`.
- завершённое обычное закрытие каждого из двух дней.

Для разбора или передачи результата в LLM:

```bash
pnpm operational-reality:gate \
  -- --from 2026-07-15 --to 2026-07-17 --format json \
  > /tmp/timeskein-operational-reality-gate.json
```

Проверить, что обычный периодический отчёт строится на том же диапазоне:

```bash
pnpm report:period \
  -- --from 2026-07-15 --to 2026-07-17 \
  --profile weekly-review --format json \
  --output /tmp/timeskein-operational-reality-period.json
```

Провал шлюза не означает плохой рабочий день. Он означает, что конкретный продуктовый сценарий ещё не был проверен или не оставил нужных данных. Код завершения `1` и строка pnpm `[ELIFECYCLE]` у строгого gate ожидаемы, пока хотя бы одна проверка не выполнена.

## Критерий принятия

Слой принимается, когда шлюз проходит и пользователь может привести хотя бы один конкретный случай, где проекция помогла выбрать или продолжить работу, а сохранённое основание позволило не восстанавливать контекст по памяти.
