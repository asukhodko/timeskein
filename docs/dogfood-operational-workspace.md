## Что проверяем

Operational Workspace должен заменить несколько конкурирующих представлений
текущей работы одним контуром:

- договор дня собран из существующих дел или направлений;
- в договоре есть 2–3 активных направления, одно первое действие, 1–3
  припаркованных конкурента и короткое основание выбора;
- договор остаётся видимым после старта и используется для возвращения;
- рядом видны текущий фокус и основания из Рабочей реальности;
- полный список дел нужен для поиска и обслуживания, но не служит параллельным
  планом дня;
- пересмотр создаёт новую версию и не переписывает утренний выбор;
- обычные старт, переключение, capture, исправление таймлайна и закрытие дня не
  ухудшились.

## Каждый из трёх дней

### Утро

1. В `Рабочем контуре` нажми `Собрать договор дня`.
2. Если активного таймера нет, Timeskein сам начнёт `Вход в день` в зоне
   `Координация`. Если сейчас учитывается другое дело, осознанно нажми
   `Переключить на координацию`; редактор договора останется открытым.
3. Выбери 2–3 существующих дела или направления, которые действительно в игре.
4. Выбери одно существующее дело как первое действие. Если активным выбрано
   направление, первое дело должно находиться внутри него.
5. Припаркуй 1–3 главных конкурента, к которым сегодня легко сорваться.
6. Одним предложением запиши, почему этот набор и первое действие достаточно
   важны сейчас.
7. Сохрани договор и начни работу кнопкой `Начать первое действие` или
   `Начать отсюда` в его карточке. Активная координация штатно переключится на
   выбранное дело.

Не веди параллельный список `что сегодня активно` во внешнем блокноте. Внешние
материалы и длинные рабочие записи пока допустимы; запрещён именно второй
оперативный active-set, который пришлось бы согласовывать с Timeskein.

### После заметного перерыва

Минимум в двух из трёх дней вернись через тот же рабочий контур:

- если договор всё ещё честный, нажми `Вернуться по договору`;
- если контекст изменился, нажми `Пересмотреть после перерыва`, поправь набор,
  парковку, первое действие или основание, сохрани новую версию и начни первое
  действие. При отсутствии активного таймера координация начнётся автоматически.

Если перед открытием редактора уже учитывалось другое дело, кнопка будет
называться `Переключить на координацию`: Timeskein не прерывает текущий фокус
без явного действия.

Хотя бы в один день обязательно сохрани новую версию договора. Не делай
искусственную правку: пересмотри договор после реального изменения дня.

### В течение дня

- стартуй и возобновляй выбранную работу из `Рабочего контура`;
- используй строку фокуса для незапланированного нового дела, если реальность
  действительно изменилась, а затем приведи договор в соответствие;
- captures, смысловые записи и исправления блоков выполняй обычными средствами;
- раскрывай `Дела` только для поиска, создания, исправления или классификации,
  затем снова сворачивай полный список.

### Вечер

1. Останови активный фокус.
2. Пройди обычную `Проверку перед отчётом` до финального состояния.
3. Скопируй финальный отчёт и сохрани его:

```bash
pnpm dogfood:finish:save
```

День засчитывается только при событии штатного завершения закрытия. Не нужно
делать отдельный идеальный отчёт ради этой вехи: важно, чтобы новый рабочий
контур не сломал принятый вечерний путь.

## Онлайн-контроль

Текущую накопленную фактуру можно проверять после любого дня. Верхняя дата не
включается:

```bash
pnpm operational-workspace:gate -- --from YYYY-MM-DD --to YYYY-MM-DD
```

До третьего дня команда ожидаемо вернёт `не пройдено`, но точно покажет, чего
не хватает: дней с договором и стартом, возвратов, ревизии или закрытий.

Историю договоров можно выгрузить отдельно:

```bash
pnpm export:operational-workspace -- --from YYYY-MM-DD --to YYYY-MM-DD
```

## Финальный gate

После третьего дня укажи верхнюю границу на день позже последнего прогона:

```bash
pnpm operational-workspace:gate -- --from YYYY-MM-DD --to YYYY-MM-DD
```

Gate требует:

- 3 дня с item-backed договором;
- 3 дня со стартом первого действия из договора;
- 3 штатных закрытия дня;
- возврат через договор минимум в 2 дня;
- минимум 1 день с сохранённой ревизией;
- целые цепочки версий без молчаливой перезаписи;
- отсутствие ошибок, пересечений фокус-блоков и стартов через старую текстовую
  диспетчеризацию.

После зелёного gate отдельно зафиксируй три смысловых ответа:

1. Понадобился ли внешний active-list?
2. Можно ли было после перерыва понять текущий выбор и парковку без
   реконструкции по памяти?
3. Стал ли основной экран одним рабочим контуром, или какие-то представления
   по-прежнему приходилось согласовывать вручную?

Только после зелёной команды и этих ответов веха переводится в `done`,
актуализируются выводы, roadmap и opskarta, затем выполняются финальные commit
и push.
