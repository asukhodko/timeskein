# Working Memory Bridge: реальная приёмка

## Зачем нужен этот прогон

Кодовая поверхность Working Memory Bridge готова, но цель проверяет не наличие
таблиц и кнопок. Нужно доказать, что после реальных пауз Timeskein возвращает в
долгое дело без внешнего блокнота и реконструкции хода работы по памяти.

Выбери одно настоящее долгосрочное дело. Не создавай учебный пример только ради
gate. Остальными функциями Timeskein и другими делами можно пользоваться как
обычно.

## Текущее состояние на 8 августа

С 30 июля по 7 августа Timeskein использовался в семь настоящих рабочих дней:
зафиксировано `52:13:58` и 104 входа, включая `12:18` и 24 входа по делу
`ППП`. Основной трекинг стабилен: ошибок старта и остановки и пересечений
фокус-блоков не обнаружено. При этом в этот период не появились новые записи
рабочей памяти, материалы, причинные следы остановки или запуски через точку
возвращения.

Этот период сохранён как естественная исходная линия до эксперимента. Он
показывает, что обычная работа сама по себе не доказывает Working Memory Bridge
и что приёмку нельзя засчитать задним числом. Отсчёт D0 по-прежнему не начат.

Мягкий gate за период `2026-07-23..2026-08-09` показал:

- 4/6 записей рабочей памяти, из них 1/3 смысловых;
- 0 материалов и 0 редакций;
- 5 именованных этапов и 2 перехода;
- 11 снимков дневного результата;
- 0/2 полных следов `результат → изменение → следующий шаг`;
- 0 возвратов после пауз;
- назначенный Track, построенный в UI профиль `work-item-reentry` и прежние
  экспорты обоих профилей; финальные экспорты всё равно потребуются после D11.

У выбранного дела до старта нового фокус-блока нужно добавить свежую смысловую
запись и материал, проверить активный этап и дневной результат, затем завершить
блок полной причинной цепочкой. Отдельно для полного gate понадобится
отредактировать одну запись. Только такой день считается D0.

После этого последовательность считается как D0, D1, D4 и D11. До выполнения
всех условий ниже не следует считать календарную паузу уже начавшейся.

## Что уже доказано автоматически

Календарный прогон проверяет продуктовую пользу, а не базовую сохранность
данных. До него автоматические проверки уже подтверждают:

- память, материал, этап, дневной результат, снимок фокус-блока и следующий шаг
  переживают закрытие агента и повторное открытие той же SQLite-базы;
- удалённые записи остаются в хронологии как tombstone, но не могут закрыть
  требования D0, материала, смысловых записей или причинного следа;
- Markdown содержит канонический JSON, который буквально равен JSON-проекции
  Local API;
- интерфейс показывает предпросмотр того же Markdown, который копируется и
  сохраняется через CLI;
- окно рабочей памяти проверено на ширине 1280 и 720 пикселей: колонки
  перестраиваются, горизонтального переполнения нет, длинный Context Pack имеет
  собственную ограниченную прокрутку.

Поэтому D0–D11 не нужно превращать в повторную проверку хранения или в
специальный UX-тест. Нужно честно работать над выбранным долгим делом и
проверить, хватает ли сохранённой памяти для реального возврата.

Не требуется каждый день собирать договор, объяснять все разрывы или закрывать
день. Обязательны только действия с выбранным долгим делом в D0, D1, D4 и D11.
В остальные дни Timeskein остаётся обычным трекером.

## Запланированный прогон

Текущий кандидат — настоящее дело `ППП`:

```text
Work Item: 6f763920-6b77-4398-8895-ecdb9f0b55d6
Track: 5e2ea50e-82f1-4c6c-8292-28243378bc64
D0:  10 августа 2026
D1:  11 августа 2026, не раньше времени завершения D0
D4:  14 августа 2026, не раньше чем через 72 часа после D1
D11: 21 августа 2026, не раньше чем через 168 часов после D4
```

Даты являются планом, а gate измеряет фактическое время. Если реальная работа
потребует открыть `ППП` раньше контрольной точки, не откладывай нужную работу
ради эксперимента: продолжи через рабочую память, а следующую паузу отсчитывай
заново. Честный сдвиг даты полезнее искусственного соблюдения календаря.

После каждой контрольной точки проверяй прогресс мягким gate. Верхняя дата не
включается:

```bash
cd /Users/a.sukhodko/dalamar81/timeskein

# После D0
pnpm working-memory:gate -- --work-item 6f763920-6b77-4398-8895-ecdb9f0b55d6 \
  --from 2026-08-10 --to 2026-08-11 --soft-fail

# После D1
pnpm working-memory:gate -- --work-item 6f763920-6b77-4398-8895-ecdb9f0b55d6 \
  --from 2026-08-10 --to 2026-08-12 --soft-fail

# После D4 и D11 подставь следующий день как --to.
```

## Граница эксперимента

- Ход выбранного дела, решения и следующий шаг хранятся в Timeskein.
- Внешние документы разрешены как рабочие материалы, но добавь их в память дела
  как URL или путь к файлу.
- Не храни единственную копию следующего шага или объяснения решения во внешнем
  блокноте.
- Между контрольными возвратами не открывай выбранный Work Item в фокусе: gate
  измеряет паузу от предыдущего фокус-блока.
- Реальная последовательность пауз `1 → 3 → 7` занимает не меньше 11 дней:
  например, работа в D0, D1, D4 и D11. В остальные дни Timeskein можно
  использовать для других дел.

## Что считается D0

Обычный рабочий день с выбранным делом ещё не запускает эксперимент. D0
начинается, когда для одного настоящего долгого дела выполнены все условия:

- в тот же местный календарный день до старта блока создана хотя бы одна новая
  запись рабочей памяти и добавлен материал;
- создан именованный этап и сохранён наблюдаемый результат дня;
- после этой настройки проведён реальный фокус-блок;
- остановка блока сохранила результат, изменение состояния и следующий шаг.

День, завершённый без этих следов, остаётся полезной исходной точкой, но не
засчитывается как D0 и не запускает отсчёт пауз.

## Подготовка в D0

После обновления кода один раз собери и запусти проверенную версию:

```bash
cd /Users/a.sukhodko/dalamar81/timeskein
pnpm dogfood:start:verified
```

Полная проверка специально занимает время. Для следующих контрольных возвратов
запускай уже собранный `Timeskein.app` как обычное приложение. Если нужен запуск
из репозитория без повторной сборки и preflight:

```bash
pnpm dogfood:continue
```

1. Выбери или создай долгосрочный Work Item и назначь ему основной Track.
2. Добавь его в договор дня и укажи наблюдаемый результат на сегодня.
3. Выдели или запусти дело и нажми видимую кнопку `Память` в строке выбранного
   дела или в карточке активного фокуса. Запасной путь: разверни список дел,
   выдели дело и нажми `N`.
4. Создай и активируй первый именованный этап.
5. До запуска фокус-блока добавь минимум один материал: URL, путь к файлу или
   текст. Подходит как специальная запись `Материал` в рабочей памяти, так и
   ссылка или файл, прикреплённые непосредственно к Work Item.
6. До запуска фокус-блока добавь новую смысловую запись: мысль, вопрос, решение
   или наблюдение. Gate не засчитает подготовку, дописанную задним числом после
   работы.
7. Отредактируй хотя бы одну запись и проверь её `Историю`.
8. Проведи реальный фокус-блок. При остановке заполни все три поля:
   `что сделал`, `как изменилось состояние`, `следующий физический шаг`.
9. Скопируй дневной отчёт и проверь раздел `По этапам`: текущий блок должен
   иметь снимок этапа и дневного результата, а не текущее переименованное
   значение из карточки дела.

## Контрольные возвраты

### После паузы не менее одного дня

1. Запусти Timeskein обычным способом.
2. Не восстанавливай контекст из внешних заметок.
3. Открой `Рабочую память`, прочитай точку возвращения и нажми
   `Начать отсюда`.
4. Проверь, что стартовал сохранённый этап и понятен следующий шаг.
5. Останови блок с новым полным следом
   `результат → изменение → следующий шаг`.
6. Заверши первый этап и активируй второй.

### После следующей паузы не менее трёх дней

Повтори возврат только через `Рабочую память` и `Начать отсюда`. Кнопка должна
создать новый фокус-блок; повторный вызов для уже активного блока возвратом не
считается. Зафиксируй, хватило ли показанных изменений, вопросов, материалов и
следующего шага без восстановления по памяти. После работы снова сохрани полный
причинный след именно у созданного возвратом блока.

### После следующей паузы не менее семи дней

Повтори тот же путь. Это главный пользовательский gate: работа должна начаться
из сохранённого следующего шага, а не из повторного исследования старого
контекста. Возврат без `результат → изменение → следующий шаг` gate не
принимает.

## Context Pack

В памяти дела открой сначала профиль `Дело`, затем `Направление`. Для каждого
профиля скопируй Markdown и JSON. Это даёт UI-доказательство обоих профилей и
обоих форматов.

Сохрани воспроизводимые файлы через CLI, пока приложение запущено:

```bash
pnpm context-pack -- --profile work-item-reentry --scope WORK_ITEM_UUID \
  --format both --output /tmp/timeskein-work-item-reentry
pnpm context-pack -- --profile track-reentry --scope TRACK_UUID \
  --format both --output /tmp/timeskein-track-reentry
```

Идентификаторы можно получить из локальной базы:

```bash
DB="$HOME/Library/Application Support/Timeskein/timeskein.db"
sqlite3 -readonly "$DB" "SELECT id, title FROM work_items WHERE deleted_at IS NULL ORDER BY updated_at DESC;"
sqlite3 -readonly "$DB" "SELECT t.id, t.title FROM tracks t JOIN work_item_tracks w ON w.track_id = t.id WHERE w.work_item_id = 'WORK_ITEM_UUID';"
```

## Текущий контроль

Gate можно запускать в мягком режиме после каждого возврата. Верхняя дата не
включается. Даты трактуются как границы местного календарного дня:

```bash
pnpm working-memory:gate -- --work-item WORK_ITEM_UUID \
  --from YYYY-MM-DD --to YYYY-MM-DD --soft-fail
```

Он показывает, чего ещё не хватает: записей, редакции, материала, этапов,
дневного результата, причинных следов, возвратов или Context Pack.
Строка `Стадия эксперимента` различает `подготовку D0`, `D0`, `D1`, `D4` и
`D11`. Ширина переданного диапазона дат не считается прогрессом: наблюдаемый
срок начинается только с полного базового блока D0. События возвращения до D0
игнорируются, а паузы 1, 3 и 7 дней принимаются только в хронологической
последовательности.
Возврат засчитывается только когда в точке возвращения был сохранён следующий
шаг, успешное нажатие `Начать отсюда` создало точно связанный фокус-блок, а его
остановка сохранила полный причинный след. Соседний ручной старт не подменяет
это доказательство.

Если во время проверки объединяешь дубль, сначала сверь их Track. При разных
направлениях Timeskein намеренно откажет в merge: назначь обоим правильный Track
и повтори объединение. Это защищает классификацию от молчаливой потери.

## Финальная проверка

После последнего возврата сначала обнови оба профиля Context Pack в интерфейсе
и скопируй каждый в Markdown и JSON. Старые проекции, построенные до финального
возврата, не подтверждают итоговое состояние. Затем укажи `--to` как следующий
календарный день:

```bash
pnpm working-memory:gate -- --work-item WORK_ITEM_UUID \
  --from YYYY-MM-DD --to YYYY-MM-DD
pnpm test
pnpm typecheck
pnpm lint
pnpm dogfood:preflight
pnpm smoke:macos-app
pnpm roadmap:validate
pnpm smoke:dogfood-docs
git diff --check
```

Цель принимается только при зелёном строгом gate и содержательном ответе на
вопрос: «Я действительно продолжил дело без внешнего блокнота и ручной
археологии?» Если gate зелёный, а контекст пришлось восстанавливать по памяти,
продуктовая приёмка не пройдена.
