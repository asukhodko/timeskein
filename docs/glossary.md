# Глоссарий Timeskein

Централизованный справочник терминов проекта. Все документы должны использовать эти определения единообразно.

---

## Основные сущности

### Work Item

Элемент работы (task/project/question), который пользователь хочет держать "в оперативной памяти".

**Атрибуты:**
- `title` — краткое имя
- `state` — состояние (`active`, `waiting`, `blocked`, `done`, `someday`, `unknown`)
- `note` — следующий шаг / что ждём / блокер
- `refs` — привязки к "миру"
- `last_seen` — когда пользователь в последний раз "трогал" этот элемент
- `pinned` — закреплён ли в инвентаре

**Уровень:** Level 0+

### Ref (Reference / Привязка)

Якорь для связи Work Item с внешним контекстом.

**Виды:**
- `url` — веб-адрес
- `file_path` — путь к файлу
- `issue_key` — ключ тикета (например, `ABC-123`)
- `repo_issue` — ссылка на issue/PR в репозитории
- `domain` — доменное имя
- `custom` — произвольная строка

**Уровень:** Level 0+

### Event (Событие)

Атом наблюдения — факт, зафиксированный системой.

**Виды:**
- **WorkItemEvent** — изменение Work Item (создание, смена состояния, редактирование заметки и т.д.). Уровень: Level 0+.
- **ContextEvent** — событие внешнего контекста (смена окна, URL вкладки, idle и т.д.). Уровень: Level 2+.

### Artifact (Артефакт)

Вложение к событию — тяжёлые данные с ограниченным временем жизни.

**Примеры:** скриншот, фрагмент текста, транскрипт.

**Канонический тип для Evidence-Mode:** chunk (серия кадров). Отдельные frames — только derived/temporary для дистилляции, не хранятся как самостоятельные артефакты.

**Уровень:** Level 3 (опционально)

### Evidence Artifact (Артефакт доказательства)

Chunk — чувствительный артефакт с TTL, захваченный в Evidence-Mode.

**Канонический тип:** chunk (обязательно). Frames — только derived/temporary для дистилляции, не хранятся как отдельные артефакты.

**Хранение:** blob-store, индексируется.

**TTL:** настраиваемый (рекомендуется 72h для privacy-first baseline).

**Уровень:** Level 3

### Episode (Эпизод)

Интервал с единым контекстом — производная сущность, генерируемая из событий.

**Назначение:** основная единица для поиска "что я делал в момент X".

**Уровень:** Level 2+ (производное представление)

### Timeline Card (Карточка таймлайна)

Derived view/presentation of Episode — UI-представление эпизода.

**Назначение:** view-model для отображения эпизодов в интерфейсе, не новая доменная сущность. Может опционально ссылаться на evidence artifacts.

**Атрибуты:**
- `time_range` — временной диапазон
- `summary` — краткое описание
- `refs` — привязки
- `marks` — метки
- `evidence_pointers` — опциональные ссылки на артефакты (Level 3)

**Хранение:** derived cache (episode_card_cache), пересчитываемо.

**Уровень:** Level 2+

### Thread (Нить)

Сквозная тема/проект/проблема, связывающая эпизоды и Work Items.

**Уровень:** Level 2+ (производное представление)

### Mark (Метка)

Пользовательский маркер для событий или эпизодов.

**Примеры:** "важно", "закрыл", "вернуться", "проект X".

**Уровень:** Level 0+ (для Work Items), Level 2+ (для событий)

### Distraction Mark (Метка отвлечения)

Авто-mark/label на эпизоде, классифицирующий активность как off-task.

**Назначение:** классификация активности, НЕ механизм исключения данных. Используется для аналитики и самоанализа.

**Настраиваемость:** да (пользователь может определить критерии off-task).

**Уровень:** Level 3

## Архитектурные компоненты

### TS-AGENT (Device Agent)

Локальный агент на устройстве — центральная точка правды.

**Функции:**
- Хранение данных (SQLite)
- Приём событий от источников
- Применение политик приватности
- Обслуживание запросов от Surface
- Запуск задач дистилляции

**Уровень:** Level 0+

### Surface (Поверхность)

UI-клиент для взаимодействия с агентом.

**Примеры:** CLI, системный трей, мобильное приложение.

**Принцип:** Surface не хранит истину — только отображает и передаёт команды агенту.

**Уровень:** Level 0+

### SourceNode (Источник событий)

Компонент, поставляющий события в агент.

**Примеры:** Collector (активное окно), Connector (расширение браузера), Extension (плагин).

**Атрибуты манифеста:**
- `source_id` — уникальный идентификатор
- `version` — версия источника
- `capabilities` — список возможностей
- `permissions` — требуемые разрешения
- `event_types` — типы генерируемых событий
- `sensitivity_defaults` — уровни чувствительности по умолчанию

**Уровень:** Level 2+

### Collector (Коллектор)

Источник событий, работающий в фоновом режиме (always-on).

**Примеры:** Active window watcher, AFK/idle detector.

**Уровень:** Level 3

### Provider (Провайдер)

Абстракция AI-провайдера для обработки артефактов.

**Типы:**
- `local` — обработка на устройстве (privacy-first)
- `remote` — облачный AI-сервис

**Атрибуты:**
- `privacy_mode` — индикатор приватности (отображается в UI)
- `data_leaves_device` — покидают ли данные устройство
- `capabilities` — список возможностей обработки

**Уровень:** Level 2+

### Connector (Коннектор)

Источник событий, работающий по явному действию или с минимальной автоматизацией.

**Примеры:** Browser extension (по команде "захватить контекст"), GitHub integration.

**Уровень:** Level 2

### Hub (Хаб)

Серверный компонент для синхронизации между устройствами.

**Уровень:** Level 1+

## Политики и контроль

### Capture Profile (Профиль захвата)

Профиль захвата данных, определяющий уровень автоматизации сбора контекста.

**Уровни:**
- **Level 0:** Manual-first — без фонового сбора
- **Level 2:** Semantics-first — явный захват по команде
- **Level 3:** Full context — always-on collectors (opt-in)

**Назначение:** позволяет пользователю контролировать глубину автоматического сбора данных.

**Уровень:** Level 0+

### Evidence-Mode (Режим доказательств)

Режим Level 3 (строго opt-in) для захвата screen evidence chunks и их дистилляции в Cards/Episodes.

**Ключевые свойства:**
- Строго opt-in — никогда не включается по умолчанию
- Chunking model — захват сериями кадров/чанков, не одиночными скриншотами
- TTL для артефактов — автоматическое удаление по истечении времени
- Purge по команде — пользователь может удалить артефакты в любой момент

**Гарантии доверия:** explicit opt-in, pause/resume, TTL, purge, revoke.

**Философия:** Evidence-Mode — сенсор для восстановления контекста, НЕ трекер дисциплины. Work Items остаются источником истины.

**Уровень:** Level 3

### PolicyGate (Шлюз политик)

Компонент, применяющий правила приватности на входе событий в агент.

**Функции:**
- Проверка denylist (домены, приложения)
- Редакция чувствительных данных
- Применение уровней чувствительности

**Уровень:** Level 0+ (базовый), Level 2+ (расширенный)

### Provenance (Провенанс)

Проверяемое происхождение данных — метаданные о том, откуда пришла информация.

**Атрибуты:**
- `source_id` — какой источник создал данные
- `timestamp` — когда
- `policy_applied` — какие правила были применены
- `provider_id` — какой провайдер обработал данные (для derived данных)
- `capture_profile_id` — какой профиль захвата был активен

**Назначение:** позволяет удалить все данные от конкретного источника при отзыве доверия.

**Уровень:** Level 2+

### Pairing (Сопряжение)

Процесс одобрения нового источника событий.

**Принцип:** новый источник не начинает кормить память, пока его явно не одобрили.

**Уровень:** Level 2+

### Purge (Очистка)

Удаление evidence artifacts (ephemeral) и связанных индексов/пойнтеров по команде пользователя.

**Область действия:** evidence artifacts + evidence pointers. НЕ удаляет derived Timeline Cards/Episodes.

**Результат:** Derived представления сохраняются как Distilled Snapshots, помечаются "evidence purged".

**Аудит:** создаёт tombstone event (evidence.artifact_purged).

**Отличие от Revocation:** Purge удаляет только ephemeral артефакты, сохраняя derived ценность. Revocation удаляет canonical + ephemeral и пересчитывает derived.

**Уровень:** Level 3

### Redaction Rule (Правило редакции)

Механизм исключения/редакции данных на входе PolicyGate.

**Назначение:** privacy exclusion — исключение чувствительных данных до их сохранения.

**Доступные типы правил по уровням:**
- **Level 0:** ref/domain denylist
- **Level 2+:** apps/domains/patterns
- **Level 3:** evidence-specific exclusions (приложения, окна, паттерны контента)

**Отличие от Distraction Mark:** Redaction Rule — механизм исключения данных (privacy). Distraction Mark — классификация активности (analytics).

**Уровень:** Level 0+ (расширяется по уровням)

### Revocation (Отзыв)

Отключение источника + удаление всех данных с его provenance.

**Область действия:** canonical events + ephemeral artifacts по source_id.

**Обработка derived:** пересчёт derived представлений без данных этого источника, или удаление derived если пересчёт невозможен.

**Назначение:** используется при отзыве доверия к источнику.

**Аудит:** логируется.

**Отличие от Purge:** Revocation удаляет canonical + ephemeral и пересчитывает derived. Purge удаляет только ephemeral, сохраняя derived как Distilled Snapshots.

**Уровень:** Level 2+

### Sensitivity Level (Уровень чувствительности)

Атрибут данных для применения политик retention/redaction.

**Назначение:** технический атрибут, НЕ пользовательская метка (Mark). Определяет политики хранения и обработки.

**Уровни:**
- **normal:** обычные данные, TTL 90d
- **private:** приватные данные, TTL 7d
- **high:** высокочувствительные данные, TTL 24h

**Применение:** автоматически назначается на основе источника, типа данных и правил PolicyGate.

**Уровень:** Level 2+

## Обработка данных

### Distillation (Дистилляция)

Процесс превращения сырых событий и артефактов в производные представления.

**Результаты:** Episodes, Threads, итоги дня.

**Уровень:** Level 2+

### Retention (Удержание)

Политика хранения данных с учётом TTL.

**Слои данных:**
- **Canonical** — события/журналы (append-only, долгоживущие)
- **Derived** — эпизоды/нити/индексы (пересчитываемые, но возможны Distilled Snapshots)
- **Ephemeral** — тяжёлые артефакты (с TTL)

**Уровень:** Level 2+

### Distilled Snapshot (Дистиллированный снимок)

Derived представление, сохраняемое после удаления upstream-сырья.

**Назначение:** сохранение извлечённой ценности после Purge evidence artifacts.

**Свойства:**
- Не пересчитываемое (upstream данные удалены)
- Содержит извлечённую информацию (summary, refs, marks)
- Помечается "evidence purged"

**Пример использования:** Timeline Cards после purge evidence — карточки сохраняются с summary и refs, но без возможности просмотра исходных артефактов.

**Уровень:** Level 2+

### Storage Budget (Бюджет хранилища)

Лимит хранилища для артефактов Evidence-Mode.

**По умолчанию:** 5 GB (настраиваемо).

**Действия при достижении лимита:**
- warning — предупреждение пользователя
- accelerated GC — ускоренная сборка мусора
- stop capture — остановка захвата

**Уровень:** Level 3

### TTL (Time To Live)

Время жизни данных — после истечения данные удаляются или редуцируются.

**Принцип:** "Distill before forget" — перед удалением сырых данных система обязана обновить производные представления.

**Уровень:** Level 2+

## Уровни зрелости

| Уровень | Название | Описание |
|---------|----------|----------|
| **Level 0** | Manual-first | Ручной реестр Work Items без фонового наблюдения |
| **Level 1** | Sync | + Синхронизация между устройствами |
| **Level 2** | Semantics-first | + Явный захват контекста по команде; connectors |
| **Level 3** | Full context | + Always-on collectors по включению пользователя |

## Плоскости системы

### Data Plane (Плоскость данных)

Канонические события, артефакты, сущности — как они хранятся и передаются.

### Control Plane (Плоскость управления)

Управление источниками, разрешениями, политиками, здоровьем системы.

**Функции:**
- health/status агента и источников
- list/enable/disable источников
- pause/resume сбора
- управление pairing
- запуск задач дистилляции
