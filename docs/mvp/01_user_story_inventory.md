# User Story: MVP-фича “Инвентарь текущей работы”

## Название

**Инвентарь текущей работы** (Current Work Inventory)

## Короткое описание

Пользователь в любой момент может увидеть список актуальных задач/проектов/вопросов и их состояние, а также быстро обновить состояние и открыть связанный контекст (ссылку/файл/тикет).

## User Story

**Как** пользователь, который ведёт несколько параллельных задач,  
**я хочу** в любой момент получить список того, что сейчас актуально, и увидеть состояние каждого элемента,  
**чтобы** быстро восстановить “что у меня на столе” и понять следующий шаг, не полагаясь на память и разрозненные вкладки.

## Основные понятия

- **Work Item** — элемент работы (task/project/question), имеющий:
  - заголовок (title),
  - состояние (state),
  - “последний раз трогал” (last_seen),
  - короткую заметку (next step / что ждём / блокер),
  - привязки (refs) к миру: URL/файл/тикет/репозиторий.

- **Актуальный** — Work Item, который:
  - в состоянии `active|waiting|blocked`, или
  - закреплён (pinned), или
  - был затронут недавно (в пределах окна давности) и не `done`.

## Acceptance Criteria (критерии приёмки)

1) **Просмотр инвентаря**
- Есть команда/экран “Инвентарь”, который показывает список Work Items.
- Для каждого Work Item видно: `title`, `state`, `last_seen` (в относительном виде), `note` (если есть).
- Список отсортирован: pinned сверху, затем active, затем blocked/waiting, затем по last_seen.

2) **Обновление состояния**
- Пользователь может за ≤2 действий поменять состояние Work Item на одно из:
  `active`, `waiting`, `blocked`, `done`, `someday`, `unknown`.
- Изменение состояния записывается и сохраняется после перезапуска агента.

3) **Создание/привязка к текущему контексту**
- Пользователь может создать новый Work Item “из текущего контекста”:
  заголовок по умолчанию берётся из title вкладки или заголовка окна (с возможностью поправить).
- Пользователь может привязать текущий контекст (URL/файл) к существующему Work Item.
- После привязки последующие посещения того же “сильного ref” обновляют `last_seen` соответствующего Work Item.

4) **Открытие контекста**
- Пользователь может открыть “последнюю привязку” (URL/файл) Work Item из инвентаря.

5) **Приватность в MVP**
- Есть базовые настройки исключений (denylist) по приложениям/доменам.
- Есть “Pause” (пауза сбора), которая немедленно останавливает запись контекста.

6) **Работа оффлайн**
- Фича полностью работает без сети.

## Примеры сценариев (Gherkin)

### Сценарий 1: Проверить, что сейчас актуально
- **Given** у пользователя есть несколько Work Items
- **When** пользователь открывает “Инвентарь”
- **Then** он видит список актуальных элементов, их состояние и последний контакт с ними

### Сценарий 2: Зафиксировать новый элемент работы
- **Given** пользователь открыл вкладку с тикетом `ABC-123`
- **When** он нажимает “Создать Work Item из текущего контекста”
- **Then** создаётся Work Item с title из вкладки и ref на URL тикета

### Сценарий 3: Поставить “жду ответа”
- **Given** Work Item “Ответ от дизайнера по API” существует
- **When** пользователь меняет состояние на `waiting` и добавляет заметку “жду ревью до пятницы”
- **Then** Work Item отображается в инвентаре как waiting с заметкой

## Out of Scope (для MVP)

- Автоматическая кластеризация эпизодов и построение нитей (Threads)
- Семантический поиск по содержимому
- Скриншоты/аудиозапись по умолчанию
- Обязательные интеграции с Jira/GitHub/Slack (достаточно refs из URL/заголовков)
- Кросс-девайс синхронизация
