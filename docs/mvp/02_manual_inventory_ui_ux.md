## Назначение документа

Этот документ описывает, как для пользователя должен выглядеть и ощущаться Manual-first инвентарь (user-story `docs/mvp/02_user_story_manual_inventory.md`), и через какие точки входа пользователь выполняет действия.

Цель — зафиксировать UX-решения до дизайна компонентов/модулей и RFC по реализации.

Ключевая особенность: Manual-first означает отсутствие фонового онлайн-наблюдения за действиями пользователя в ОС (без watcher активного окна, без захвата экрана/ввода, без автоматического чтения вкладок). Система работает только на явных действиях пользователя внутри Timeskein.

---

## Продуктовое обещание (как это должно звучать "в голове пользователя")

* Timeskein — это короткий список рабочих элементов (Work Items) с состоянием, следующим шагом и ссылками на контекст.
* Я могу за 10–60 секунд:

  * вспомнить, что у меня сейчас на столе,
  * быстро вернуться по ссылке/пути,
  * отметить "я снова здесь" (touch),
  * изменить состояние (делаю/жду/блокер/готово),
  * зафиксировать следующий шаг.
* Timeskein ничего не записывает в фоне и ничего не "подглядывает", пока я сам не вызываю палитру и не делаю действие.

---

## UX-цели

1. Скорость

* Базовые действия: 1–2 шага, преимущественно с клавиатуры.
* Вызов интерфейса: моментально (глобальный хоткей).

2. Минимальная когнитивная нагрузка

* Инвентарь должен быть понятным "с первого взгляда".
* Состояния и сортировка должны соответствовать интуиции.

3. Явность и доверие

* Пользователь должен понимать: данные попадают в систему только по явному действию.
* Оффлайн, локально, без экрана/аудио.

4. Стабильная база для будущего роста

* UX не должен ломаться при появлении сборщиков контекста (в будущем).
* Manual-first механика остаётся полезной даже после добавления автоматизации.

---

## Ограничения и честные компромиссы Manual-first

1. `last_seen` в этой версии — это "последний явный touch/изменение/открытие ref через Timeskein", а не "когда я реально смотрел этот контекст в другом приложении".

2. "Создать Work Item из текущего окна/вкладки" недоступно как универсальная функция. В MVP пользователь создаёт item и добавляет refs вручную.

3. Инвентарь — не таймлайн активности. Он предназначен для восстановления контекста задач и управления ими.

## Основная модель взаимодействия: три UX-поверхности

### 1) Глобальная палитра команд (основная поверхность)

Форма: небольшое overlay-окно поверх всех приложений, вызываемое глобальным хоткеем.
Внутри: список Work Items + поле поиска/команд.

Зачем: палитра делает Timeskein "инструментом на 10 секунд" без переключения в отдельное приложение.

Основные свойства:

* открывается/закрывается мгновенно (Esc закрывает),
* полностью управляется клавиатурой,
* поддерживает поиск по title и note,
* поддерживает быстрые действия по одной клавише.

### 2) Трей/менюбар-иконка (вторичная поверхность)

Форма: иконка с меню:

* Open Inventory
* Quick Add
* Settings
* Quit

Зачем:

* прозрачная точка контроля (приложение запущено),
* привычная "точка входа" без хоткея,
* доступ к настройкам и диагностике.

### 3) Полный экран управления (редко используемая поверхность)

Форма: локальная страница (127.0.0.1) или отдельное окно.
В MVP может быть минимальной или вообще отложенной, но UX-идея фиксируется.

Зачем:

* более подробное управление refs,
* просмотр истории событий (если включим `work_item_events`),
* настройка denylist и политик приватности,
* экспорт/импорт/backup.

## Что должно быть установлено на компьютере

Минимальная установка для Manual-first:

1. Timeskein App (один пакет)

* включает UI (палитра + трей) и локальный core,
* хранит данные локально (SQLite).

2. Локальная БД

* SQLite-файл в user data directory.

3. Опционально: CLI-обёртка

* удобна для power users и для тестирования,
* не обязательна для UX.

### Разрешения ОС

В Manual-first мы стремимся к "почти нулевым" разрешениям:

* глобальный хоткей (стандартная регистрация, без "Accessibility" уровня чтения ввода),
* открытие URL/файлов через системные handlers (по действию пользователя),
* чтение clipboard может использоваться только по явной команде "Add ref from clipboard" (не фоновое чтение).

Никаких разрешений на запись экрана/аудио, accessibility-логгирование, мониторинг окон/ввода.

## Точки входа и базовые команды

### Рекомендуемый хоткей по умолчанию

* Windows/Linux: Ctrl+Shift+Space
* macOS: Cmd+Shift+Space

Хоткей задаётся на первом запуске (можно изменить в настройках).

### Ментальная модель палитры

Палитра работает как:

* быстрый поиск по Work Items,
* действия над выбранным item,
* быстрые "команды" в строке ввода.

---

## Представление Work Item в списке (карточка одной строки)

Каждая строка в списке должна показывать:

* pin-метка (если pinned)
* state (как короткий бейдж/иконка)
* title (основной текст)
* last_seen (компактно: "3h", "2d", "—")
* note (усечённо до 1 строки)
* индикатор refs (например: "⎘2" или "refs:2")

Пример (условно):

* 📌 active   ABC-123: Ошибка валидации…      3h   Next: уточнить контракт…
* blocked    Доступ к staging                 5d   Waiting for: права в Vault
* waiting    Ответ от дизайнера               2d   Next: проверить макеты
* someday    Идея: автоматизировать отчёт     12d  —

---

## Навигация и шорткаты (ядро UX)

Набор быстрых действий должен быть стабильным и видимым (в подсказке снизу палитры).

### Базовые

* Enter: Open (открыть основной ref / выбор ref, если их много)
* Esc: закрыть палитру
* ↑/↓: выбрать item
* Ctrl+N (или "+"): создать новый item (или команда `add`)

### Быстрые действия над выбранным item

* T: Touch (обновить last_seen)
* N: Edit note
* S: Set state (меню состояния)
* P: Pin/unpin
* R: Ref actions (add/manage/open)
* Del/Backspace: (опционально) удалить item (если поддерживаем soft delete)

### Быстрая смена состояния (power user вариант)

Опционально, но очень полезно в manual-first:

* 1: active
* 2: blocked
* 3: waiting
* 4: someday
* 5: unknown
* 6: done

Это ускоряет "проставить реальность" без лишних окон.

---

## Командная строка в палитре (не обязательно, но желательно)

Палитра может поддерживать команды в стиле:

* `add <title>`
* `touch`
* `state active|blocked|waiting|done|someday|unknown`
* `note <text>`
* `pin` / `unpin`
* `ref add` (по умолчанию из clipboard)
* `ref paste` (ввести вручную)
* `open` / `open ref`

Важно: пользователь не обязан знать команды. Команды существуют как ускоритель и как API-форма для будущего CLI.

## UX-потоки по действиям из user-story

Ниже описаны эталонные потоки. Реализация UI может отличаться деталями, но должна сохранять количество шагов и ощущение скорости.

### Поток 1: Открыть инвентарь и увидеть актуальное

1. Пользователь нажимает хоткей.
2. Открывается палитра со списком.
3. Список отсортирован: pinned → state-rank → last_seen.

Критично:

* никаких дополнительных экранов,
* поиск доступен сразу (курсор в поле ввода).

### Поток 2: Создать новый Work Item "на ходу"

Вариант A (через команду):

1. Hotkey
2. `add <title>` → Enter
3. Item создан, last_seen = now.

Вариант B (через форму):

1. Hotkey
2. Ctrl+N → мини-форма:

   * Title (обязательно)
   * State (по умолчанию active или unknown)
   * Note (опционально)
   * Refs (опционально)
3. Save

UX-ускоритель:

* После создания предложить:

  * `R` добавить ref,
  * `N` добавить note,
  * `S` поменять state.

### Поток 3: Touch, чтобы "поднять" задачу наверх

1. Hotkey
2. выбрать item стрелками
3. нажать T
4. визуальный feedback "touched" (0.3–0.8 сек)
5. item поднимается наверх по last_seen.

### Поток 4: Изменить state

Вариант быстрый:

1. Hotkey
2. выбрать item
3. нажать цифру состояния (1–6)

Вариант через меню:

1. Hotkey
2. выбрать item
3. S → список состояний → Enter

Оба варианта должны:

* обновить `updated_at` и `last_seen`,
* сразу отразиться в сортировке.

### Поток 5: Обновить note (следующий шаг)

1. Hotkey
2. выбрать item
3. N → открывается редактор note
4. ввод → Enter сохраняет, Esc отменяет

UX-деталь:

* note лучше делать многострочным, но показывать в списке только 1 строку.

### Поток 6: Pin/unpin

1. Hotkey
2. выбрать item
3. P

Эффект:

* item становится pinned,
* перемещается в верх списка pinned-группы.

### Поток 7: Добавить ref (вручную)

1. Hotkey
2. выбрать item
3. R → меню:

   * Add from clipboard
   * Paste manually
   * Pick file…

Сценарии:

* clipboard: самый частый, 1–2 шага.
* file picker: реже, но нужен для людей, которые часто работают с локальными документами.

### Поток 8: Ref дедупликация и конфликт

Если пользователь добавляет ref, который уже привязан к другому item, система должна показать конфликт прямо в палитре.

Пример:

This ref is already linked to:

* ABC-123: Ошибка валидации… (active, 3h)

Actions:

* O: open existing
* A: attach anyway
* Esc: cancel

Это защищает качество данных manual-first режима.

### Поток 9: Открыть контекст (Open last ref)

1. Hotkey
2. выбрать item
3. Enter

Правила:

* если refs = 0: показать подсказку "No refs. Press R to add."
* если refs = 1: открыть его
* если refs > 1: открыть primary/последний, либо предложить быстрый chooser

Открытие ref должно обновлять last_seen, потому что это явное действие внутри Timeskein.

## Denylist и приватность в UX

Поскольку refs добавляются вручную, denylist тоже должен срабатывать только в момент добавления ref.

UX-правила:

* если домен в denylist и политика block:

  * отказ + понятное сообщение "Domain is blocked by privacy settings".
* если политика redact_to_domain:

  * сохранить вместо полного URL укороченный ref (например `domain:mail.google.com`)
  * сообщить, что ref был редактирован по правилам приватности.

Важно: UI должен объяснять, что это не ошибка, а защита.

## First-run onboarding (первый запуск)

Onboarding нужен не "про фичи", а про доверие и привычку.

Рекомендуемая последовательность:

1. Экран "что Timeskein делает и чего не делает"

* делает: хранит Work Items, которые ты добавляешь сам
* не делает: не записывает экран, не собирает окна, не следит за клавиатурой, не отправляет в облако

2. Выбор хоткея

3. Мини-обучение (30–60 секунд)

* add item
* add ref from clipboard
* touch
* open

4. Пустой инвентарь + "Create first Work Item".

---

## Ошибки и крайние случаи (UX-ожидания)

1. ref не открывается (файл удалён / приложение не найдено)

* показать понятное сообщение,
* предложить "Edit refs".

2. пользователь попытался добавить пустой ref

* не добавлять,
* показать подсказку.

3. пользователь добавляет ref, который выглядит как URL, но невалиден

* можно сохранить как custom (если это осознанно),
* либо попросить уточнить тип.

4. конфликт refs

* обязательное предупреждение (см. поток 8).

---

## "Сигналы качества" (как понять, что UX получился)

Это не метрики аналитики, а проверки поведения:

* Создать Work Item с title+ref можно за 10–20 секунд без мыши.
* Touch занимает 2–3 секунды.
* Вернуться к контексту (open) — за 5 секунд.
* Пользователь в конце дня видит в инвентаре правду:

  * active = действительно делаю,
  * waiting/blocked = действительно жду/заблокирован.

---

## Не-цели (не делаем в этом UX-документе)

* Автоматическое создание Work Items из контекста активного окна.
* Автоматическое обновление last_seen по реальному посещению вкладок/файлов.
* Таймлайн, эпизоды, нити, семантический поиск по экрану/аудио/контенту.

Эти вещи могут появиться позже без пересборки UX, но они не входят в Manual-first MVP.

---

## Совместимость с будущим (как этот UX не ломается при росте)

Когда появятся collectors/online-наблюдение, добавятся новые команды, но базовая модель не меняется:

* палитра остаётся главным интерфейсом,
* state/note/pin остаются ручной истиной пользователя,
* появятся команды типа "Capture current context" или "Suggest ref from current app",
* last_seen сможет обновляться автоматически, но touch остаётся как явный сигнал.

## Путь к расширению UX (Level 2/3)

### Новые команды в палитре (Level 2)

При появлении connectors:

* **"C" — Capture context**: захватить текущий контекст (окно/вкладка) и предложить создать/привязать Work Item
* **Suggestions**: при вводе показывать подсказки "Похоже на ABC-123"
* **Auto-complete refs**: предлагать refs на основе текущего контекста

### Новые индикаторы (Level 2/3)

* **Source badge**: откуда пришёл ref (manual / browser / IDE)
* **Auto-seen indicator**: отличать ручной touch от автоматического last_seen
* **Health status**: статус подключённых источников в трее

### Настройки источников (Level 2/3)

Появится новый экран в Settings:

* Список подключённых SourceNodes
* Кнопки Enable/Disable per source
* Revoke (отключить + удалить данные)
* Pairing flow (одобрение новых источников)

### Принцип сохранения доверия

**Автоматика не должна:**
* Перезаписывать ручные `state` и `note`
* Создавать Work Items без подтверждения пользователя
* Собирать данные без явного включения источника

**UX должен показывать:**
* Откуда пришли автоматические данные (provenance)
* Какие источники сейчас активны
* Как отключить/удалить данные от источника

## Будущее: Evidence-Mode (Level 3)

Evidence-Mode — это строго opt-in функция Level 3, которая добавляет возможность захвата экрана. Она **не входит в MVP** и требует явного согласия пользователя.

### Интеграция с Manual-first UX

При включении Evidence-Mode в будущем:

* **Палитра остаётся главным интерфейсом** — Evidence-Mode добавляет новые команды, но не меняет базовую модель
* **Timeline Cards** — новый способ просмотра Evidence Artifacts (см. [03_evidence_mode_ui_ux.md](03_evidence_mode_ui_ux.md))
* **Новые команды**: pause/resume capture, purge evidence, manage providers
* **Storage Budget** — управление объёмом хранимых evidence artifacts

### Новые элементы UX (Level 3)

* **Evidence indicator в трее**: показывает статус захвата (active/paused/disabled)
* **Provider selector**: выбор источника захвата (local/remote)
* **Purge controls**: удаление evidence artifacts с сохранением Distilled Snapshots
* **Redaction Rules**: настройка правил приватности для исключения контента

### Принципы интеграции

1. **Opt-in only**: Evidence-Mode никогда не включается по умолчанию
2. **Явный контроль**: пользователь всегда видит, что захват активен
3. **Приватность**: Redaction Rules и Sensitivity Levels защищают данные
4. **Обратимость**: Purge удаляет evidence, но сохраняет Distilled Snapshots

## Итоговые UX-решения, которые считаются принятыми (для перехода к дизайну)

1. Основной интерфейс Timeskein в Manual-first MVP — глобальная палитра (hotkey overlay).
2. Есть трей/менюбар и минимум настроек (hotkey, denylist, экспорт).
3. Все действия выполняются только по явной инициативе пользователя (no background observation).
4. Набор шорткатов фиксирован: Enter/open, T/touch, N/note, S/state, R/refs, P/pin.
5. Добавление ref по умолчанию поддерживает clipboard и дедупликацию с конфликт-диалогом.
