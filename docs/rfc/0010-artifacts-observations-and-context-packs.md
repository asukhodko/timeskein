# RFC-0010: Артефакты, наблюдения и Context Pack

## Статус

**Manual slice implemented, 2026-07-22; real acceptance pending.** Ручные
материалы и профили Context Pack для Working Memory Bridge реализованы.
Observation, Derivation, автоматический захват, каскадное удаление внешних
источников и Context Fabric остаются проектом будущих вех и не разрешены этим
статусом.

## Цель

Определить минимальный контракт, который позволяет Timeskein:

- сохранять ручные материалы уже в ближайшей вехе;
- позднее принимать наблюдения из приложений, браузера, Chronicle и других
  SourceNodes без параллельных моделей данных;
- строить переносимый контекст для интерфейса, отчётов и разных ИИ;
- отделять пользовательские факты от недоверенного содержимого и машинных
  интерпретаций;
- удалять сырьё и его производные в соответствии с намерением пользователя.

## Не входит в этот RFC

- выбор базы данных или векторного индекса;
- реализация screen capture;
- MCP-сервер, облачная синхронизация или конкретный LLM-провайдер;
- универсальная таблица всех событий;
- автоматическое изменение Work Item, Track или решений.

## 1. Модель записей

### 1.1. Artifact

Материал или указатель на материал. Вручную добавленный файл и автоматический
снимок экрана используют общий смысловой контракт, но могут иметь разные
политики хранения.

Минимальные поля:

```text
artifact_id
kind
source_id
device_id
captured_at | interval_start + interval_end
temporal_precision
sensitivity
storage_class
expires_at
content_digest
locator
content_trust = untrusted
```

`locator` может указывать на локальный blob, файл, URL или внешний объект.
Точный источник предпочтительнее копии содержимого, если он остаётся доступным
и достаточным для пользовательской задачи.

### 1.2. Observation

Факт о наблюдении, а не вывод о работе пользователя.

```text
observation_id
source_id
artifact_id?
observed_at
recorded_at
schema_version
sensitivity
content_trust = untrusted
focus_session_id?
work_item_id?
track_snapshot?
correlation_id?
payload
```

Пример допустимого утверждения: «в 14:37 активным было приложение X».
Недопустимый автоматический переход: «пользователь продуктивно работал над
Track Y».

### 1.3. Derivation

Пересчитываемая интерпретация одного или нескольких артефактов, наблюдений или
канонических событий.

```text
derivation_id
kind
input_ids[]
created_at
schema_version
derivation_version
provider_id?
model_id?
prompt_version?
processing_location
confidence?
payload
invalidated_at?
```

Если вход удалён, исправлен или отозван, производная запись пересчитывается,
помечается недействительной или удаляется согласно политике.

### 1.4. Accepted Claim

Явно принятое пользователем утверждение, созданное из Derivation или вручную.
Оно материализуется существующей причинной записью: результатом, состоянием,
решением, следующим действием, подтверждением или исправлением.

Accepted Claim хранит ссылку на предложение машины и входные данные. Принятие
не превращает недоверенное содержимое источника в инструкцию.

### 1.5. Context Pack

Версионированная, воспроизводимая проекция для конкретного потребителя и цели.
Это продуктовый результат, но не новая сущность истины.

```text
pack_id
profile
audience
purpose
as_of
scope
input_ids[]
facts[]
recent_actions[]
changes[]
decisions[]
unknowns[]
refs[]
next_actions[]
trust_summary
redactions[]
generated_at
schema_version
```

Первые профили:

| Профиль | Пользовательский результат |
| --- | --- |
| `work-item-reentry` | Понять, где остановился и какое действие доступно сейчас |
| `track-reentry` | Восстановить состояние долгого направления после паузы |
| `period-reflection` | Передать проверяемую фактуру для обзора и решения |
| `meeting-brief` | Подготовить цели, последние решения, хвосты и доказательства |

Markdown, JSON, UI и запрос к модели являются представлениями одного пакета.

## 2. Граница доверия

### 2.1. Входное содержимое

Любой внешний текст, OCR и импортированная память получают
`content_trust: untrusted`. Они никогда не добавляются в system/developer
инструкции модели и не могут сами разрешить вызов инструмента.

### 2.2. Извлечение

Извлекатель работает как ограниченное преобразование:

1. получает только нужный фрагмент и контекст схемы;
2. не имеет инструментов записи или выполнения команд;
3. возвращает результат по строгой схеме;
4. сохраняет provider/model/prompt/schema provenance;
5. маркирует цитаты, предположения и неизвестности раздельно.

### 2.3. Использование агентом

Рабочий агент получает `Context Pack`, а не неограниченный поток сырого
содержимого. Цитаты источников остаются данными. Действие, влияющее на внешний
мир или пользовательскую истину, проходит обычное подтверждение.

## 3. Политика хранения и удаления

Каждый Artifact и его Derivations входят в граф происхождения. Для удаления
нужен явный режим:

| Режим | Сырьё | Уже существующие производные | Новая дистилляция |
| --- | --- | --- | --- |
| `expire-and-preserve` | удалить по TTL | сохранить разрешённый снимок | допустима политикой |
| `purge-raw` | удалить сейчас | сохранить только уже разрешённое | только по отдельному согласию |
| `forget-completely` | удалить | удалить или инвалидировать каскадно | запрещена |
| `revoke-source` | удалить данные источника | пересчитать без источника | не создавать из отозванного сырья |

Аудит хранит метаданные операции без секретов и удалённого содержимого.
Шифрование at rest и ключ в системном хранилище являются обязательным gate до
первого пассивно захваченного чувствительного артефакта.

## 4. Работа с Chronicle и другими источниками

Chronicle может быть полезен как низкодетализированный импорт производной
памяти:

```text
source_kind = openai_chronicle
record_kind = derived_memory
temporal_precision = approximate
content_trust = untrusted
processing_location = remote
```

Импортёр должен:

- читать только явно выбранные файлы или каталог;
- не считать Markdown стабильным протоколом Chronicle;
- сохранять путь, время импорта и доступный временной диапазон;
- не выдавать пересказ Chronicle за первичное наблюдение;
- позволять удалить импорт и все зависящие от него производные записи.

Такой адаптер рассматривается только после общего SourceNode contract. Он не
нужен для Working Memory Bridge и Bounded Context Probe.

## 5. Инкрементальный маршрут

### Working Memory Bridge

- ввести ручной `Artifact/Material`;
- строить `work-item-reentry` и `track-reentry` Context Pack из существующих
  ручных данных;
- проверить возврат через 1, 3 и 7 дней без внешнего блокнота.

Реализованный срез использует исторические записи `work_memory_entries` и их
неизменяемые редакции. Ручной материал хранится как текст, URL или путь к файлу
с происхождением и временем; бинарное содержимое не копируется. Context Pack
строится детерминированно на заданный `as_of`, имеет явные scope, факты,
неизвестности, предупреждения, redactions и provenance и одинаково доступен в
UI, Markdown и JSON. Продуктовая приёмка остаётся открытой до реальных возвратов
после пауз 1/3/7 дней.

### Causal Period Review

- использовать `period-reflection` Context Pack как единый переносимый пакет;
- сохранять принятые выводы и решения обратно в причинную память;
- повторным обзором проверять их последствия.

### Bounded Context Probe

- реализовать observation envelope и trust gate;
- собирать активное приложение и при возможности URL только внутри ручного
  Focus Session;
- screen content не входит в первый probe;
- сравнить полезность пакета с ручным следом.

### Context Fabric

- обобщить только доказавшие пользу источники в SourceNode adapters;
- добавить health, pairing, revocation и единый граф происхождения;
- рассмотреть Chronicle как один необязательный импортёр.

## 6. Критерии готовности модели

1. Ручной Artifact может войти в Context Pack без SourceNode и ИИ.
2. Один Context Pack одинаково представляется как JSON, Markdown и UI.
3. У пакета видны scope, `as_of`, входные записи, неизвестности и redactions.
4. Внешний текст не может стать инструкцией или молча изменить пользовательское
   состояние.
5. Производная запись воспроизводима или честно помечена невоспроизводимой.
6. `forget-completely` не создаёт новый summary и удаляет зависимые данные.
7. Поставщик модели можно заменить без миграции канонической памяти.
8. Новый SourceNode не требует новой параллельной модели доверия и хранения.

## Открытые вопросы

- какие ручные материалы достаточно хранить как Ref, а какие как локальный blob;
- нужен ли отдельный пользовательский статус для принятого машинного claim;
- какой минимальный Context Pack заметно сокращает время возврата;
- какие derived данные можно синхронизировать, а какие лучше пересчитать;
- как показывать неполный каскад удаления при недоступном внешнем источнике.
